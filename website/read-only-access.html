Read-only access

Read-only by design.

Exactly which roles Sentrigis needs in Azure, AWS and Google Cloud, and what it can and cannot do with them.

One rule: read, never change

Sentrigis scans your clouds with read-only identities, then adds a second guard in the product itself: every request to a cloud API goes through a wrapper that only lets read calls through, and blocks the read calls that return secrets or data. The connection is tested before it is saved.

The roles you grant

Microsoft Azure

The built-in Reader role on each subscription (or a management group above them). The scanner only makes list and get calls, and blocks list calls that return secrets.

AWS

The AWS managed policies SecurityAudit and ViewOnlyAccess on a dedicated read-only role. Only describe, list and get calls are allowed; object reads, Lambda code, SSM parameters, Secrets Manager values and EC2 password data are blocked.

Google Cloud

The roles roles/viewer and roles/iam.securityReviewer on a service account. Only read methods are allowed; object reads, Secret Manager and token or signing methods are blocked.

Setup

Copy one script into Azure Cloud Shell, AWS CloudShell or Google Cloud Shell. It creates the read-only identity; Sentrigis checks it can read before saving, and tells you which role is missing if it cannot. Your first scan starts immediately.

What you get

An inventory of your cloud resources, misconfigurations mapped to CIS and Microsoft benchmarks, internet exposure and attack paths, all in the same console as your endpoints and IT assets.
